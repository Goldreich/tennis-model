# Tennis Model

A reproducible point-by-point Monte Carlo model for ATP and WTA match
forecasting.

The model estimates player serve and return performance from historical match
data, anchors matchup strength with surface-specific Elo, applies a temporary
match-day fitness adjustment, and simulates complete matches under legal tennis
scoring. Match, player, and compound prop probabilities are derived from the
same joint simulation paths.

> **Current framework:** Tennis Model v1.2  
> **Frozen base:** Tennis Model v1.1  
> **Archived baseline:** Tennis Model v1.0  
> **Runtime:** Python 3.12

This is a research and probabilistic-forecasting project. It does not use
bookmaker odds, prediction-market probabilities, or crowd forecasts as model
inputs.

## Forecasts

The simulation framework supports probabilities and distributions for:

- match winner and exact match score;
- match duration and total games;
- deciding-set and lopsided-set outcomes;
- tiebreak occurrence and tiebreak counts;
- player aces and double faults;
- first-serve points won;
- player winners and unforced errors;
- player-to-player count comparisons; and
- compound propositions derived from the same simulated match paths.

Every supported prop is evaluated from complete match simulations rather than
being estimated independently. This preserves dependencies between match
length, score, serve counts, rally outcomes, and the winner.

## Methodology

### Serve and return components

The point model begins with five causal serve components:

| Component | Meaning |
|---|---|
| **F** | Probability that the first serve is in |
| **A** | Ace probability conditional on a first serve being in |
| **Q1** | Server-win probability on a returnable first serve |
| **D** | Double-fault probability after a missed first serve |
| **Q2** | Server-win probability on a playable second serve |

ATP and WTA models are fitted separately. The component models account for the
server, returner, surface, recency, and estimation uncertainty while preserving
the causal order of a service point.

For each simulated match path, the model draws uncertain component parameters
and match-level performance values. Those values are reused throughout that
path rather than redrawn point by point.

### Matchup strength

Tennis Model v1.1 added a surface-specific Elo anchor to the serve-component
model. Elo supplies independent information about overall player strength that
may not be fully represented by the available serve statistics.

The Elo anchor modifies the playable first- and second-serve point
probabilities through the frozen v1.1 strength-integration rule. It does not
directly alter ace, double-fault, or first-serve-in propensities.

### Match-day fitness

The model retains each player's underlying Elo as the long-run strength
estimate. A temporary game-day adjustment accounts for documented workload and
retirement risk when constructing a specific matchup.

This adjustment affects the match forecast without permanently treating
fatigue or a short-lived physical limitation as a change in player ability.

### Winners and unforced errors

Tennis Model v1.2 adds a rally-termination layer for winners and unforced
errors. Player effects are initialized from retained historical evidence and
updated sequentially using Bayesian posteriors as new match observations become
available.

The layer is conditional on the point and match paths generated by the existing
model. It therefore extends the simulation without replacing the frozen serve,
Elo, fitness, scoring, or duration mechanisms. Under the versioned counting
policy, aces and double faults are included in the corresponding winner and
unforced-error totals.

### Match simulation

The scoring engine simulates legal tennis matches point by point, including:

- advantage games;
- continuous service order;
- standard and deciding-set tiebreaks;
- best-of-three and best-of-five formats;
- exact set and match termination;
- breaks of serve and break-point opportunities; and
- retirement handling under the configured policy.

Duration, serve statistics, rally outcomes, and settlement quantities are
attached to these same paths.

## Model versions

| Version | Status | Principal contribution |
|---|---|---|
| **v1.0** | Archived | Five-component serve/return model, scoring engine, duration, retirement, simulation, and immutable locks |
| **v1.1** | Frozen base | Surface Elo strength anchor and temporary match-day fitness |
| **v1.2** | Active | Winners/unforced-errors rally layer with sequential Bayesian player updates |

Probability-affecting changes require an explicit model-version change.
Engineering refactors and performance optimizations must preserve the
probabilities defined by the active specification.

## Quick start

The project uses [uv](https://docs.astral.sh/uv/) for its reproducible Python
environment.

~~~powershell
uv sync --extra dev
~~~

Run the automated checks:

~~~powershell
uv run pytest
uv run ruff check .
uv run mypy src/tennis_model
~~~

Inspect the maintained batch-simulation interface:

~~~powershell
uv run python scripts/simulate_usopen_match_batch.py --help
~~~

Live tournament forecasting is configuration-driven and requires local source
snapshots and fitted artifacts. See
[USOPEN_LIVE_WORKFLOW.md](docs/USOPEN_LIVE_WORKFLOW.md) for the operational
workflow.

## Reproducibility

Numerical forecasts are designed to be reproducible from:

- the immutable source snapshot and information cutoff;
- model, configuration, and fitted-artifact identifiers;
- canonical player and match identities;
- the code version;
- the simulation seed and path policy;
- the information scenario; and
- the settlement-policy version.

Stochastic interfaces use explicit random-number generators. Prediction locks
are immutable and content-addressed, and new information creates a new lock
revision rather than overwriting an earlier forecast.

Related props are evaluated from the same simulated paths. Unsupported or
unresolved settlement cases are represented explicitly rather than guessed.

## Data and publication boundary

External dataset payloads, fitted artifacts, source captures, prediction locks,
and simulation outputs are intentionally excluded from Git:

| Local path | Contents |
|---|---|
| **data/** | Raw and processed source data |
| **artifacts/** | Fitted models, snapshots, captures, and prediction locks |
| **outputs/** | Generated forecast and analysis reports |

The repository versions source manifests, configuration, provenance schemas,
content hashes, reconstruction scripts, and model code. A clone therefore
contains the methodology and reconstruction machinery, but not third-party data
or private forecast artifacts.

Historical serve data are attributed to Jeff Sackmann / Tennis Abstract through
the retained [ATP](https://github.com/Kadantte/tennis_atp) and
[WTA](https://github.com/VictorSquidWei/tennis_wta) repositories under their
stated [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/)
terms. Additional exact-date and current-tournament sources are retained
locally according to their respective publication and licensing boundaries.

Raw inputs are never silently repaired or overwritten. Invalid observations are
preserved with anomaly information, and unavailable derived quantities remain
missing rather than being converted to zero.

## Limitations

- Forecast quality depends on the coverage and quality of the retained source
  data.
- Match-day fitness cannot capture every undisclosed injury, illness, or
  tactical limitation.
- Winners and unforced errors depend partly on official scorer conventions.
- Elo is an overall-strength proxy and does not encode every matchup-specific
  interaction.
- Monte Carlo estimates retain finite-sample uncertainty even when the
  underlying model is fixed.
- Model calibration and comparative performance must be evaluated
  out-of-sample; a strong result in one tournament is not conclusive evidence of
  general superiority.

## Research use

This repository is intended for statistical research, reproducible forecasting,
and model evaluation. Its outputs are probabilistic estimates, not guarantees
or financial advice.
